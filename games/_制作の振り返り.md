# 実験場の制作を振り返る

記録日：2026-09-21。Gitは `9d3d0ee` までを参照。

目的は、新作の初稿で過去と同じ修正を繰り返さないこと。
持ち主の人格や作風を断定する記録ではなく、制作中の判断と、その判断から得た仮説を残す。
作業ルールは直下の `AGENTS.md`、実装手順は `games/README.md` が正本。
この記録の傾向より、今回の依頼と新しい修正指示を優先する。

## 調べた範囲と確かさ

- **会話で確認**：直近の制作タスク「牛歩シミュレーターを開く」「同時競技5種を続ける」「実験場に手刀ゲームを追加」「実験場にサメ歩行ゲーム追加」「実験場にゲームを追加」（100連スロット）の、読み取れた制作指示。加えて、このタスクでの共通化・プレビュー重複解消・振り返りの依頼。
- **履歴で確認**：主に9月14〜21日のゲーム関連コミット。水切り・わんこなどは、それ以前の履歴とゲーム内の記録も補助的に参照した。操作の補正を外した変更など、一部は差分まで確認した。
- **推定**：複数の例からまとめた初稿の方針。コミットされたことだけを「持ち主が満足した証拠」としない。会話の全件や、別の制作道具での全履歴を読めたわけではない。

会話の全文、添付ファイルの個人用パス、制作と関係ない話題は転載しない。
根拠のコミットは末尾にまとめた。古い変更には、その後の取り下げがある。

## 全体として見えた方向性【推定】

**変な題材や極端な状況を、実際に触って起きる出来事として成立させる。**
牛が宇宙を壊す、複数競技を同時にする、サメの手足を動かす、
一輪車で熱いものを食べる、といった核は極端でも、
押したもの・動いたもの・ぶつかった場所・鳴った音のつながりは丁寧に直している。

初稿で大切なのは、機能の数よりも「この操作で、このおかしな出来事が起こる」が伝わること。
そのうえで、主役の形、画面の見やすさ、音の質、間を詰める傾向がある。
題材から勝手に新しいギャグ文や説明を追加する、という意味ではない。

## 次の初稿に活かす判断

### 1. 操作した量・向き・瞬間が、画面の反応につながっている

【会話・履歴】牛ではスワイプの余韻、踏み込み、景色の流れ、衝突位置と土煙の遅れを調整。
サメでは「これもなんか進行補正してる？」「車輪素直に進みすぎちゃうからもっと物理ベースでOK」と修正している。[根拠A・B]

初稿では、操作→体や道具の動き→接触・結果→音、を一続きで確認する。
物理の面白さが核なら、勝手に前進させたり姿勢を起こしたりして成功へ誘導しない。
力を加えるなら、画面の右向きなのか、体が向いている方向なのかまで合わせる。
一方、操作の分かりやすさや反応の良さまで捨てるわけではない。
サメの車輪の力や支えるばねも強めている。全作品を厳密な物理計算にする指定ではない。

### 2. 見るべき物をはっきりさせ、背景と操作欄は邪魔をしない

【会話】同時ボールではボタンを下げて飛来エリアへ寄る、コート線を細く半透明にする。
手刀では人物と床、サメではジェットと背景の色が溶ける問題を修正した。[根拠C・D]

初稿の画角は、主役の大きさだけでなく、次に何が来るかを見られる余白も含めて決める。
小さいスマホ幅で、主役・対象物・背景・ボタンの重なりと明暗差を見る。
輪郭や軌跡は対象を見つける助けとして使い、背景の線や装飾を同じ強さで目立たせない。
「常にカメラを寄せる」ではない。スロットでは複数リールが見えるよう引く判断もある。

### 3. 主役や道具は、簡略化しても何であるか、どう動くかが分かる形にする

【会話】牛の首が不自然で作り直し、同時ボールの球の模様・手足・持ち物を調整。
サメでは操作アイコンを実際のパーツに合わせ、車輪の関節とばねの役割を直した。[根拠B・E]

初稿でも、向き、握り方、関節、接地、物同士の大きさ、代表的な模様を先に確かめる。
細部を増やす前に、輪郭と部品のつながりを整える。
道路にビルが出る、衝突していない位置で人が飛ぶ、物が手前で消えるなど、
場面の筋が通らないところは、題材の荒唐無稽さと分けて直す。
全作品を写実的にしたり、3Dに統一したりする根拠にはしない。

### 4. 音・揺れ・光は、操作や出来事に対応させ、強弱をつける

【会話】スロットは停止したリールのランプ、短い発光、軽い揺れ、金属・コインらしい音。
牛は衝突音を重くした後に音量を抑え、同時ボールも歓声を抑えて拍手を目立たせた。[根拠F]

初稿から核になる操作音と反応を合わせる。衝突音は衝突の瞬間・強さと対応させる。
環境音は舞台を感じさせつつ、操作音を埋めない量にする。
音を「鳴るか」だけでなく、「何の音に聞こえるか」「連続して聞いて疲れないか」で確認する。
光・揺れ・残像をすべて常時強くするのではなく、通常の反応と節目を分ける。
掛け声の常用や合成音への統一は好みとして固定しない。スロットの掛け声は後に休止した。

### 5. 足した文字や操作は、役割を見て減らしている

【会話・履歴】牛の途中の文を削除、同時ボールの行動文字を削除、
サメの2／4切り替えは編集時だけ表示、スロットの番号は10刻みにした。[根拠G]

画面の初稿は、依頼された文字と、その場面で使う操作から組む。
操作・選択は対象物の絵で伝えられるかを考える。
ただし、文字や数字を全部なくすという意味ではない。
一輪車では「食べる／飲む」を追加し、牛では速報・速度、クイズでは問題と選択肢が必要だった。
文字の有無を勝手に決める代わりに、指定された情報が主役と競合しない配置にする。
タイトル・共有文・結果文の言い回しは持ち主が具体的に決めることが多い。

### 6. 難しさや変化を増やしても、狙える余地を残す

【会話】同時ボールの速球は「むずすぎない範囲で」、変化球は「たまにだけ」。
【履歴】スロットは終盤にも目押しを狙えるよう加速を緩和した。[根拠H]

初稿では、遊び始めから特徴が見えるようにしつつ、反応時間・必要操作数・入力間隔を測る。
通常時と節目の変化を区別し、例外的な変化を常時発生させない。
サメの予測しづらい姿勢のように、うまくいかないこと自体が遊びになる場合もある。
その面白さと、押せないボタン・見えない対象・入力の取りこぼしは区別する。
残機3、10刻み、人数140などは作品ごとの値であり、新作の既定値にしない。

### 7. 成功・失敗の後にも、そのゲームらしい出来事と間がある

【会話・履歴】同時ボールは倒れて笛、サメはゴール瞬間の写真と短いスロー、
牛は暗転して「宇宙崩壊」をゆっくり表示。一輪車は鍋を戻してから声を出す。[根拠I]

初稿を「数値の結果が出る」だけで終えず、依頼された結末まで一周できるようにする。
身体の動き、物の反応、声、結果の順番と間を合わせる。
新しい結末を勝手に発明するのではなく、題材や指定にある結末を画面上で成立させる。
再挑戦で保持するもの、戻る場所、結果を読む時間も確認する。
余韻の長さは一律にしない。牛では長く、同時ボールの振り戻しでは短くする変更がある。

### 8. サムネイルと録画は、それぞれ見せたいものが違う

【会話】牛は数字なしの牧場で加速中、同時ボールは主役を球が囲む構図、
サメは操作欄を含めずサメ中心。複数作品でサムネの数字を外した。[根拠J]

サムネ初案は、主役とそのゲームの状況が分かる構図を候補にする。
余計な数字、カーソルの被り、重要な物の見切れを確認する。
これは推奨する初案であって、問題文と選択肢が主役のクイズなどには機械的に適用しない。
録画はサムネと違い、利用者に見える必要な操作欄などを含める。
「サムネから操作欄を外す」を「録画もcanvasだけでよい」に読み替えない。
手元専用の確認表示を録画から除く指定は、作品ごとの指示に従う。

## 取り下げ・戻しから学ぶこと

| 試したこと | 後の判断 | 次回に持ち越すのは |
|---|---|---|
| 牛の霧を全段階でなくす | 宇宙以外は元に戻す（`be354b0` → `a02bf2f`） | 視界を広げれば必ず良いわけではない。景色の出現・消失と奥行きで判断 |
| 同時ボールの輪郭を黄色にする | 同じ会話で黒へ戻す | 「黄色が好み」と記録せず、対象物の識別しやすさを引き継ぐ |
| サメの回転する棒の脚 | 取り下げ（`dadd66b` → `937432a`） | パーツ数を増やすこと自体を目的にしない |
| スロットの連続した掛け声 | いったん休止（`5be9a05`） | 音の追加後も、聞き続けた印象で減らす余地を残す |
| 牛のスワイプの余韻／同時ボールの振りの余韻 | 前者は伸ばし、後者は詰める（`2fb25f7`／`2f0a143`） | どちらも操作の感じを合わせた判断。長短を共通の好みにしない |

戻す指示が出たら、その変更に伴った入力・物理・カメラの条件まで戻っているかを見る。
途中の試案を、完成版の仕様や今後の必須事項として残さない。

## 初稿を作るときの使い方【提案】

実装前に、依頼から次の短い制作メモを埋める。画面に表示する文章ではない。
すでに指定されたことを質問し直さず、小さな選択はこの記録と雛形を使って進める。
遊びの核を変える未確定事項だけ、必要な時点で確認する。

| 項目 | 最初に整理すること |
|---|---|
| 核 | 何を操作すると、何が起きるのが面白いのか |
| 操作 | 押す・離す・なぞるのどこで反応し、どの量や向きを使うか |
| 主役と画角 | 主役、対象物、予告が見える範囲。スマホでのボタンとの重なり |
| 反応 | 核になる動き・音・接触位置。通常時と節目の強弱 |
| 進行 | 最初に特徴が見える場面、変化の間隔、狙える難しさ |
| 結末 | 指定された成功・失敗の動き、結果までの間、再挑戦の戻り先 |
| 文字 | 依頼された文字・タイトル・共有文。未指定の文を補作しない |
| 確認 | 開始→本編→終了を一周、縦画面、取消、音、録画、共有 |

初稿の確認順の目安は、**核の操作が成立 → 主役と対象が見える → 操作と反応が一致 → 終了まで一周 → 音と間を調整 → 細部と共有用の絵**。
新しい要素を増やす前にこの一周を見せる。進め方・公開判断・プレビューの扱いは `AGENTS.md` に従う。

## 次の制作で記録を更新するとき

新しい指示が一般的な好みか、今回だけの調整かを区別する。
何を試し、何を残し、何を戻したかを、理由が分かる範囲で記す。
理由が発言されていない場合は推定と書く。矛盾する例が出たら古い記録も訂正する。
実装上の数値や操作仕様は、そのゲームの記録・テストに残す。
ここは判断の参考資料として保ち、作業ルールを別管理する場所にはしない。
