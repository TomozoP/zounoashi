# 実験場にゲームを足す

ビルドはありません。HTML1枚 + canvas だけ。道具は `_tools/` にあります。

## いちばん短い手順

```bash
node games/_tools/new.js hoge "ほげゲーム" "ひとこと説明"
```

これで `games/_hoge/index.html` ができて、**手元の実験場タブにすぐカードが出ます**
（`_` で始まるフォルダは GitHub Pages が配信しないので、公開サイトには出ません）。

あとは `index.html` の3か所を書くだけです。

| 目印 | 書くこと |
|---|---|
| `▼UPDATE` | 進行（毎コマ）と、押した・なぞった・離したときの処理 |
| `▼DRAW` | 毎コマの絵 |
| `▼SHARE` | シェアの文 |

できたら、

```bash
node games/_tools/smoke.js games/_hoge/index.html   # 壊れていないか
node games/_tools/thumb.js hoge                     # サムネを画面から作る
node games/_tools/publish.js hoge                   # 公開の形にする
git add -A && git commit && git push origin main    # 公開（push は言われてから）
```

## 揃えるかたち

| | |
|---|---|
| 作り | HTML1枚 + canvas。ライブラリなし、ビルドなし |
| 画面 | **タテ。横540で固定、高さは端末の形に合わせて780〜1700** |
| 登録 | `full: true`（枠を作らず1ページまるごと使う） |
| 文字 | 頼まれた文字だけを出す。説明・煽り・見出し・ラベルを勝手に足さない |
| 操作 | タップとスペースキーで同じことができる（`pad.js` がジョイパッドをスペースに化けさせるため）。触るのは絵の中だけ |
| 押す間隔 | **スマホ(横375px)で44px以上。＝ゲーム座標で63以上**離す |
| リセット | Esc でいつでも最初から（押しっぱなしで連発しない） |
| 終わり方 | 結果画面に数字と「もう一度」「Xでシェア」 |
| シェア | `share.js` の `zShare`を使う。左に正方形のサムネ、右にゲーム名が並ぶ共有カードに揃える |
| 音 | 最初の操作より後でしか鳴らせない。画面を離れたら止める |
| 覗き穴 | `window.__probe` を残しておく（テストが中を見るため） |

**サイト側が用意するもの**（ゲーム側で作らなくてよい）

- 上のバーの「もどる」と「全画面」
- 開いた時点でゲームにキー入力を渡す。ジョイパッドも読んで枠へ送る
- プレイ数の集計（`id` を決めるだけ。手元で試したぶんは数えません）

## 動作確認のしかた

**ブラウザのプレビューでは遊べません。** 表に出ていない間 `requestAnimationFrame` が
止まるので、3秒待っても2〜3コマしか進みません。

- 見た目 → 開始直後の1コマをスクリーンショット
- 遊べるか → **偽のDOMの上で自動運転する**。`_tools/harness.js` がその台です

```js
var load = require("./games/_tools/harness");
var g = load("games/_hoge/index.html");
g.step(60);            // 1秒ぶん進める
g.tap(270, 400);       // ゲーム座標で触る（画面の形に関わらずこの座標）
g.press(" ");          // スペース
g.view(390, 844);      // 画面の形を変える
g.probe.now();         // ゲーム側の覗き穴
g.until(function () { return g.probe.now().state === "result"; });
```

`smoke.js` は「落ちないか」だけ見ます。**遊びとして成立するか**（正しく解けるか、
間違えたら終わるか、難しくなりすぎないか）はゲームごとにテストを書いて確かめます。
`wanko` のときは 10種類×10個・混ぜて100個・間違い6通り、を自動で回しました。

## 一覧に出るまで

共有ボタンは `/share/<id>/?card=square2` を自動で使います。ここにゲームのタイトルとサムネのOGPを置き、
開くと従来のプレイ画面へ移ります。ゲーム本体のURLにも同じOGPを設定します。
以前の `/#/game/<id>` をそのまま投稿した場合は、サイト共通のOGPになります。
`publish.js` が共有ページを作ります。公開済みゲームのタイトルやサムネを変えたら、
`node games/_tools/ogp.js` で更新してください。SVGのサムネは共有用PNGも作ります。

新しいゲームも、雛形の `share.js` と `zShare` をそのまま使い、`publish.js` で公開準備すれば
同じ表示になります。カード形式は `twitter:card = summary`（左に正方形のサムネ、右にゲーム名）。
`summary_large_image` に変えたり、ゲームごとに共有URLを組み立てたりしないでください。
`card=square2` は以前の大きいカードがXに残るのを避けるための指定で、共通処理が付けます。
公開準備の後は `node games/_tools/tests/share.js` で、共有リンクとカード設定を確認します。

- 下書きの間は `games/_local.js` に1行（`new.js` が書きます）。**localhost のときだけ**読まれます
- 公開すると `index.html` の `GAMES` に移ります（`publish.js` がやります）
- `id` は半角小文字の英数字・ハイフン。URL（`#/game/<id>`）とプレイ数の集計に使います
- サムネは正方形に切られます（`object-fit: cover`）。`thumb.js` は縦長の画面から
  「上のほう」と「下のほう」を詰めた正方形を作ります

```bash
node games/_tools/thumb.js hoge            # 3秒動かして撮る
node games/_tools/thumb.js hoge -t 8       # もっと進んだ場面で撮る
node games/_tools/thumb.js hoge --top 200  # 切り取り位置をずらす
```

裏でブラウザを画面なしで借りて**実際に遊ばせた画面**を撮ります。手は要りません。
最初にスペースを1回押すので、タイトルから始まるゲームでもそのまま中身が写ります。

SNS用の動画は、手元だけで次のように撮れます。

ローカルでゲームを開いて `F9` を押すと撮影パネルが出ます。手動・自動、
ゲームと同じ縦横比・縦・横・正方形、標準・高画質・最高画質を選べます。
手動撮影はもう一度 `F9` を押すと停止します。
右上には準備中・録画中・MP4保存中を表示し、録画中のマークでも停止できます。
このパネルとマークは `localhost`・`127.0.0.1` だけで読み込まれ、公開サイトには出ません。
雛形も同じ共通の撮影処理を使うため、録音同期の修正は新しいゲームにも適用されます。

```bash
node games/_tools/record.js hoge
node games/_tools/record.js hoge --manual  # 自分で操作し、F9で録画開始・停止
```

540×960の縦画面で自動運転し、完成した動画をデスクトップに保存します。
F9の撮影もデスクトップに保存します。ファイル名にはゲーム名と日時などが付きます。
保存係を起動したまま道具を更新したときは、`record-server.js` を再起動してください。
ゲームのcanvasと音だけを録るため、マウスカーソルやサイトの外枠は映りません。
録画フォルダはGitの対象外です。自動操作は各ゲームの `window.__recording.run` に書き、
新しいゲームには雛形から入ります。
手動撮影でもcanvasだけを録るので、操作中のマウスカーソルは動画に入りません。
F9の保存前に `node games/_tools/record-server.js` を起動しておきます。
録画停止後、手元のFFmpeg（`games/_tools/_bin/ffmpeg.exe`）でMP4へ変換して保存します。
音と絵の相対時刻を保ち、固定60fpsとシーク用の情報を持つMP4を作ります。
変換前後の控えは `games/_recordings/` に残ります。

## ジョイパッド

`games/pad.js` を1行読むだけで効きます。雛形には入っています。

```html
<script src="../pad.js"></script>
```

やっていることは、**キーに化けさせる**だけです。

| | |
|---|---|
| どのボタンでも | スペース（押した／離した、両方） |
| 十字キー・左スティック | ← → ↑ ↓ |

このサイトのゲームは「スペース＝決定・進む、矢印＝向き」で揃えてあるので、
ゲーム側に足すものはありません。Esc（やり直し）は**出しません**。
手が滑って最初からになるのを防ぐためです。

要る理由は、ゲームが枠（iframe）の中にいて、枠をクリックしていないと自分では
読めないからです。サイト側（`index.html` の `padBridge`）が読んで枠へ送り、
`pad.js` がそれを受けます。

**絵の外（黒い余白）のタップは拾いません。** 一度そうしてみましたが、
ボタンでないところを押して何か起きるのはおかしい、ということでやめました。

## 素材の画像

生成した png をそのまま置かないこと。だいたい 2MB くらいあります。webp にすると
1割前後に減ります（見た目はほぼ変わらない）。

```bash
node games/_tools/img.js "C:/Users/megus/Downloads/image (2).png" -o games/_hoge/img
node games/_tools/img.js 拾った絵/ -o games/_hoge/img -w 1080   # 横1080まで縮める
```

- まとめて渡せます。フォルダを渡すと中の画像を全部
- 出す先を書かなければ、元と同じ場所に同じ名前の `.webp` ができる
- 元のファイルは消しません
- 透過はそのまま残ります
- `-q` で画質（既定82）、`-w` / `-h` で大きさの上限、`--png` で png のまま縮小

裏で Edge か Chrome を画面なしで借りて書き出しています（Node だけでは webp を
作れないため）。手は要りません。

## 気をつけること

- **キー操作**: ページに埋め込まれて動くので、他の場所をクリックするとフォーカスが外れます。
  タップだけでも遊べるようにしておくと安全
- **更新が反映されない**: 手元では `?v=` を自動で付けているので普通のリロードで足ります。
  それでも古いときはスーパーリロード（Ctrl+Shift+R）
- **数が増える仕掛け**: 数を増やすと押す間隔が狭くなります。面板を広げる・2段にする・
  位置を左右に振る、で63以上を保つこと

## 道具（`_tools/`）

| | |
|---|---|
| `new.js` | 雛形を写して、手元の一覧に登録する |
| `smoke.js` | 落ちないかの共通確認（読み込み・30秒・画面6通り・でたらめ操作・やり直し） |
| `harness.js` | 偽DOMの台。ゲームごとのテストはこれを使って書く |
| `thumb.js` | 動いている画面からサムネ（600x600 webp）を作る |
| `record.js` | ゲームを自動運転し、手元用の縦動画を撮る |
| `img.js` | 素材の png/jpg を webp にする（縮小もできる） |
| `publish.js` | `_` を外して `GAMES` に入れる（commit と push はしない） |
| `tests/` | ゲームごとのテスト。`wanko-*.js` が書き方の見本、`pad.js` は全ゲーム共通の確認 |

`smoke.js` は `window.__probe` があるとより詳しく見ます。雛形には入っています。
別ファイルの .js に分けているゲームは `load(file, { withScripts: true })`。
