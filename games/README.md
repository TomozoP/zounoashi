# 実験場にゲームを足す

ビルドはありません。HTML1枚 + canvas だけ。道具は `_tools/` にあります。

## いちばん短い手順

```bash
node games/_tools/new.js hoge "ほげゲーム" "ひとこと説明"
```

これで `games/_hoge/index.html` ができて、**手元の実験場タブにすぐカードが出ます**
（`_` で始まるフォルダは GitHub Pages が配信しないので、公開サイトには出ません）。

あとは `index.html` の3か所を書くだけです。

| 目印 | 書くこと |
|---|---|
| `▼UPDATE` | 進行（毎コマ）と、押した・なぞった・離したときの処理 |
| `▼DRAW` | 毎コマの絵 |
| `▼SHARE` | シェアの文 |

制作中の変更はローカルHTTP配信で確認し、既存のプレビュータブを再利用して持ち主に見せます。
タブを重複させない手順は、直下の `AGENTS.md` の「制作中はローカルプレビューを開く」に従います。

```bash
node games/_tools/smoke.js games/_hoge/index.html   # 壊れていないか
# ローカルHTTP配信の最新版を開く。外部確認が必要な場合だけ下記の preview/ を更新する
git add -A && git commit && git push origin main    # 制作中の確認用。追加の承認は不要
```

完成して正式公開の指示を受けたら、

```bash
node games/_tools/thumb.js hoge                     # サムネを画面から作る
node games/_tools/publish.js hoge                   # 公開の形にする
git add -A && git commit && git push origin main    # 新しいゲームの公開は承認を受けてから
```

## 制作中の固定リンク

**通常はローカルプレビューを使います。以下は外部確認用の固定リンクが必要な場合の手順です。**
制作・修正を頼まれたら、このページへの反映まで行います。毎回の公開確認は不要です。
一覧には載せず、ゲームが変わっても同じリンクを使います。

1. ゲームごとの原本は `games/_<id>/` に残し、変更の動作を確認する。
2. 最新版の本体と必要な素材を `preview/` に反映する。既存の中身は先に確認し、
   別の制作物を失わないよう原本を残す。フォルダ全体を無条件に上書きしない。
3. 画像・音・共通処理の参照先を確認する。たとえば下書きの `../pad.js` は
   この場所では `../games/pad.js` になる。配信されない `games/_<id>/` を参照しない。
4. `preview/index.html` の検索除外指定、`preview-version`、`auto-reload.js` の読み込みを保つ。
   内容を変えたcommitごとに版を新しくし、素材・スクリプトのURLにも同じ版の `?v=` を付ける。
   絵・音・別ファイルだけの変更でも版を更新する。
5. 制作中のページでも動くことを確認し、差分を確認して `main` に commit・push する。
   公開ファイルへの反映を確認し、固定リンクを渡す。確認待ちならその旨を伝える。

自動更新は表示中に30秒ごと、画面へ戻ったとき・通信復帰時にも確認します。
更新が届くと再読み込みされ、プレイ中なら最初からになります。
制作中は正式な共有ページを作らず、共有先もこの固定リンクにします。
パスワード付きの非公開ではありません。

正式公開の指示を受けたら、最終修正を原本へ揃えてサムネを用意し、通常の
`publish.js <id>` で一覧と正式な共有ページを作ります。制作中専用の自動更新や
検索除外指定を正式版に持ち込まないよう確認します。
`/preview/` は削除・正式リンクへの恒久転送をせず、次の制作でも使えるよう残します。

### 個別の隠しリンクを指定された場合だけ

固定リンクとは別にゲーム固有のURLを頼まれた場合は、次の従来の方法も使えます。

```bash
node games/_tools/publish.js hoge --unlisted
```

動作確認後に commit・push すると、`https://www.zounoashi.com/games/hoge/` で
遊べます。フォルダは `games/hoge/` に移り、その中を更新して制作を続けます。
サイトの一覧には載らず、手元の一覧には残ります。サムネはまだなくても構いません。
検索に載せない指定も付けますが、パスワード付きの非公開ではありません。
ゲーム内の共有も、この制作中のURLを使います。

完成して正式公開の指示を受けたら、サムネを用意して次を実行します。

```bash
node games/_tools/thumb.js hoge
node games/_tools/publish.js hoge
```

commit・push 後は一覧に載り、正式リンク `https://www.zounoashi.com/#/game/hoge` と
共有カードが使えます。検索に載せない指定は外れ、制作中に渡した直接リンクも引き続き開けます。
道具は公開準備までを行います。対象ゲームの制作中公開・正式公開は、それぞれ持ち主の指示に従います。

## 揃えるかたち

新しいゲームを正式公開するかどうかなどの大きな判断は、持ち主に確認します。
制作中の固定リンクへの反映は承認済みなので、その都度の確認は不要です。
頼まれた細かい修正や道具・手順書の更新は、必要な確認を済ませて追加の許可なく
commit・push まで進めます。くわしくはリポジトリ直下の `AGENTS.md` に従ってください。

|---|---|

| 画面 | **タテ。横540で固定、高さは端末の形に合わせて780〜1700** |

## 動作確認のしかた

**ブラウザのプレビューでは遊べません。** 表に出ていない間 `requestAnimationFrame` が
止まるので、3秒待っても2〜3コマしか進みません。

- 見た目 → 開始直後の1コマをスクリーンショット
- 遊べるか → **偽のDOMの上で自動運転する**。`_tools/harness.js` がその台です

```js
var load = require("./games/_tools/harness");
var g = load("games/_hoge/index.html");
g.step(60);            // 1秒ぶん進める
g.tap(270, 400);       // ゲーム座標で触る（画面の形に関わらずこの座標）
g.press(" ");          // スペース
g.view(390, 844);      // 画面の形を変える
g.probe.now();         // ゲーム側の覗き穴
g.until(function () { return g.probe.now().state === "result"; });
```

`smoke.js` は「落ちないか」だけ見ます。**遊びとして成立するか**（正しく解けるか、
間違えたら終わるか、難しくなりすぎないか）はゲームごとにテストを書いて確かめます。
`wanko` のときは 10種類×10個・混ぜて100個・間違い6通り、を自動で回しました。

## 一覧に出るまで

### X共有・画像保存・総合共有の使い回し

新作は雛形の `share.js` と `result-actions.js` を使います。Xボタンからは必ず
`zResultActions.x` を呼びます。スマホでも端末の総合共有に切り替わりません。
既存の `zShare` は互換性のため残しています。

```html
<script src="../share.js"></script>
<script src="../result-actions.js"></script>
```

```js
// 実際のbutton要素へ一度だけ登録。本文と画像はクリック時の最新結果を渡す。
window.zResultActions.bind(xButton, function () {
  window.zResultActions.x({ text: score + '点でした #ゲーム名' });
});
window.zResultActions.bind(saveButton, function () {
  window.zResultActions.saveImage({ canvas: resultCanvas, name: '結果.png' });
});
window.zResultActions.bind(moreButton, function () {
  window.zResultActions.share({ text: score + '点でした #ゲーム名' });
});
moreButton.hidden = !window.zResultActions.canShare();
```

- `x` は本文と共通の共有URLをXへ渡します。画像ファイルは添付しません。
- `share` は端末の総合共有を開きます。非対応時は `unsupported` を返し、勝手にXへ移りません。
- `saveImage` はPCではPNGをダウンロード、対応スマホでは画像の共有シートを開きます。
  取消では何も保存せず、共有が失敗・非対応ならダウンロードへ切り替えます。
  常にダウンロードしたい場合は `native: false` を指定します。
- 保存画像の絵作りはゲーム側が担当します。DOMの見出しなども必要なら結果用canvasへ描きます。
  事前に生成した画像は `canvas` の代わりに `blob` を渡せます。
  非同期生成は結果表示時に済ませ、完成するまで保存ボタンを `disabled` にします。
  クリック後に `await`・`toBlob`・タイマーを挟んで共有すると、スマホの操作権限を失う場合があります。
- 操作は `pointerdown` で実行せず、実際のbuttonの `click` から直接呼びます。
  `bind` はゲームへの入力伝播を止め、通常のクリックとキーボード操作を残します。
  同じボタンへ二重登録せず、付け直す場合は戻り値の解除関数を呼びます。
- canvasのアイコン上に透明buttonを置く場合は、雛形のCSSと
  `zResultActions.place(button, {x,y,w,h}, W, H, 結果画面か)` を使います。
  アイコンはcanvasにも描くので録画に残ります。非表示・再挑戦時にはbuttonも隠します。
- 各操作の `done` で結果を受け取れます。Xは `opened / blocked`、総合共有は
  `shared / cancel / unsupported / error`、保存は `saved / shared / cancel / error`。
  `opened / saved` はブラウザへの依頼が済んだ意味で、投稿完了・端末への保存完了を保証しません。

画像保存・総合共有ボタンは必要なゲームにだけ追加し、操作名は「画像を保存」「共有」などを
`aria-label` に残します。雛形にはXボタンだけが入っています。
共通処理を変えたら `node games/_tools/tests/result-actions.js` と
`node games/_tools/tests/share.js` を実行します。

共有ボタンは `/share/<id>/?card=square2` を自動で使います。ここにゲームのタイトルとサムネのOGPを置き、
開くと従来のプレイ画面へ移ります。ゲーム本体のURLにも同じOGPを設定します。
以前の `/#/game/<id>` をそのまま投稿した場合は、サイト共通のOGPになります。
`publish.js` が共有ページを作ります。公開済みゲームのタイトルやサムネを変えたら、
`node games/_tools/ogp.js` で更新してください。SVGのサムネは共有用PNGも作ります。

新しいゲームも、雛形の `share.js` と `zShare` をそのまま使い、`publish.js` で公開準備すれば
同じ表示になります。カード形式は `twitter:card = summary`（左に正方形のサムネ、右にゲーム名）。
`summary_large_image` に変えたり、ゲームごとに共有URLを組み立てたりしないでください。
`card=square2` は以前の大きいカードがXに残るのを避けるための指定で、共通処理が付けます。
公開準備の後は `node games/_tools/tests/share.js` で、共有リンクとカード設定を確認します。

- 下書きの間は `games/_local.js` に1行（`new.js` が書きます）。**localhost のときだけ**読まれます
- 公開すると `index.html` の `GAMES` に移ります（`publish.js` がやります）
- `id` は半角小文字の英数字・ハイフン。URL（`#/game/<id>`）とプレイ数の集計に使います
- サムネは正方形に切られます（`object-fit: cover`）。`thumb.js` は縦長の画面から
  「上のほう」と「下のほう」を詰めた正方形を作ります

```bash
node games/_tools/thumb.js hoge            # 3秒動かして撮る
node games/_tools/thumb.js hoge -t 8       # もっと進んだ場面で撮る
node games/_tools/thumb.js hoge --top 200  # 切り取り位置をずらす
```

裏でブラウザを画面なしで借りて**実際に遊ばせた画面**を撮ります。手は要りません。
最初にスペースを1回押すので、タイトルから始まるゲームでもそのまま中身が写ります。

SNS用の動画は、手元だけで次のように撮れます。

ローカルでゲームを開いて `F9` を押すと撮影パネルが出ます。手動・自動、
ゲームと同じ縦横比・縦・横・正方形、標準・高画質・最高画質を選べます。
手動撮影はもう一度 `F9` を押すと停止します。
右上には準備中・録画中・MP4保存中を表示し、録画中のマークでも停止できます。
このパネルとマークは `localhost`・`127.0.0.1` だけで読み込まれ、公開サイトには出ません。
雛形も同じ共通の撮影処理を使うため、録音同期の修正は新しいゲームにも適用されます。

```bash
node games/_tools/record.js hoge
node games/_tools/record.js hoge --manual  # 自分で操作し、F9で録画開始・停止
```

540×960の縦画面で自動運転し、完成した動画をデスクトップに保存します。
F9の撮影もデスクトップに保存します。ファイル名にはゲーム名と日時などが付きます。
保存係を起動したまま道具を更新したときは、`record-server.js` を再起動してください。
録画にはゲーム画面のヘッダー・タブ・説明・フッター・操作ボタンも含めます。音声も録音します。
DOMの要素は window.__recording.frame() で録画用canvasへ合成できます。
録画パネル・録画中の表示・ブラウザの操作欄は映しません。
録画フォルダはGitの対象外です。自動操作は各ゲームの `window.__recording.run` に書き、
新しいゲームには雛形から入ります。
手動撮影でも同じ全要素を含めます。録画用の画面を書き出して、欠落や見切れを確認します。
ローカルプレビューは `node games/_tools/preview-server.js` で起動します。MP4保存係も自動で起動し、停止した場合も再起動します。既存の8735番の配信がある場合は、そのまま再利用します。保存係だけを手動起動する必要はありません。
録画停止後、手元のFFmpeg（`games/_tools/_bin/ffmpeg.exe`）でMP4へ変換して保存します。
音と絵の相対時刻を保ち、固定60fpsとシーク用の情報を持つMP4を作ります。
変換前後の控えは `games/_recordings/` に残ります。

## ジョイパッド

`games/pad.js` を1行読むだけで効きます。雛形には入っています。

```html
<script src="../pad.js"></script>
```

やっていることは、**キーに化けさせる**だけです。

| | |
|---|---|
| どのボタンでも | スペース（押した／離した、両方） |
| 十字キー・左スティック | ← → ↑ ↓ |

このサイトのゲームは「スペース＝決定・進む、矢印＝向き」で揃えてあるので、
ゲーム側に足すものはありません。Esc（やり直し）は**出しません**。
手が滑って最初からになるのを防ぐためです。

要る理由は、ゲームが枠（iframe）の中にいて、枠をクリックしていないと自分では
読めないからです。サイト側（`index.html` の `padBridge`）が読んで枠へ送り、
`pad.js` がそれを受けます。

**絵の外（黒い余白）のタップは拾いません。** 一度そうしてみましたが、
ボタンでないところを押して何か起きるのはおかしい、ということでやめました。

## 素材の画像

生成した png をそのまま置かないこと。だいたい 2MB くらいあります。webp にすると
1割前後に減ります（見た目はほぼ変わらない）。

```bash
node games/_tools/img.js "C:/Users/megus/Downloads/image (2).png" -o games/_hoge/img
node games/_tools/img.js 拾った絵/ -o games/_hoge/img -w 1080   # 横1080まで縮める
```

- まとめて渡せます。フォルダを渡すと中の画像を全部
- 出す先を書かなければ、元と同じ場所に同じ名前の `.webp` ができる
- 元のファイルは消しません
- 透過はそのまま残ります
- `-q` で画質（既定82）、`-w` / `-h` で大きさの上限、`--png` で png のまま縮小

裏で Edge か Chrome を画面なしで借りて書き出しています（Node だけでは webp を
作れないため）。手は要りません。

## 開始画面・スマホの音・長押し（制作時の共通ルール）

雛形の共通処理を使い、同じ処理を新しいゲームへ複製しません。

- `view.js`：`zGameView.measure(wrap, W)` で画面の高さを決め、配置計算後に `fit(canvas, wrap, ctx, W, H, view)` で表示へ反映します。タップ座標は `point(canvas, event, W, H)`。配置計算と3D画面更新の順序はゲームごとに保ちます。
- `start.js`：`zStartTap(待機中かを返す関数, 指を離したときの関数)` で開始タップを受け取ります。後者には元の出来事が渡ります。段階選択・音声起動・演出はその関数に残し、スワイプ開始など専用の操作へ無理に適用しません。戻り値は登録の解除関数です。
- `result-actions.js`：結果のボタン位置は `place` に任せます。同じ位置・表示状態の書き直しは共通側で省きます。

これらの変更後は `node games/_tools/tests/common-view-start.js`、
`node games/_tools/tests/result-actions.js` と対象ゲームのテストを実行します。
新しい動作確認は `_tools/harness.js` を使い、独自の偽DOMを増やしません。
ジョイパッドの確認は `node games/_tools/tests/pad.js ゲーム名` で対象を指定できます。省略時は全部を確認します。

音声の再開は `audio.js` の `window.zAudioResume(音声)` を使います。雛形にも入っています。
初回操作・中断後の再開・短い無音による起動補助をここにまとめ、同じ処理をゲームへ複製しません。
音声の作成、効果音の作り方、操作を受け取る場所は各ゲームに残します。
起動用の無音の長さを指定する必要がある場合は第2引数にサンプル数を渡します（既定1）。
変更後は `node games/_tools/tests/audio-start.js` と、利用するゲームの動作確認を行います。
これは処理の共通化であり、iPhone実機での音声確認の代わりにはなりません。

- 初回は待機画面と英字の「START」。ゲームの時間制限・敵・導火線はまだ進めない。待機中に見せる人物・セリフ・演出はゲームごとに決め、勝手に足さない。
- STARTは開始の目印。ボタン内だけでなく、ゲームのページ内の余白を含め、どこをタップしても開始する。サイトの「もどる」など別の操作は対象外。
- 押した瞬間でなく、同じ指を離した時点で開始する。開始タップを投球・加速・爆弾操作などへ流さない。取消では開始せず、2本目の指や右クリックも使わない。
- スペース・Enter・ジョイパッドでも開始できるようにする。テンプレートはキーを離して開始する。再挑戦と検証用の reset は直接プレイ状態へ戻す。
- STARTは主役や名前に重ねない。小さい画面でも位置を確認する。メロスでは車より下の余白に置いた。
- iPhoneでは、最初から長押しすると最初の音が欠け、いったんタップすると鳴る症状があった。ページ表示だけの自動再生や、resume()・短い無音だけで解決したと断定しない。最初の開始タップ内で音声を作成・再開してから、次の操作で遊ぶ。
- suspended だけでなく interrupted も再開の対象とし、closed は再開しない。再開の失敗は次の操作で再試行できるようにする。短い無音は補助処理であり、iPhoneで鳴ることを保証するものではない。
- 音声の再開関数を呼んだテストと、実機で音が聞こえる確認は別。PCの波形やブラウザ確認だけで「iPhoneで直った」と報告しない。
- ゲームの絵には user-select: none、-webkit-user-select: none、-webkit-touch-callout: none を設定する。touch-action: none だけでは長押し選択を防げない。pad.js はcanvas上の長押しメニューと画像ドラッグも抑える。入力欄や通常のボタンの操作を一律に止めない。
- 開始画面の白フラッシュ・効果音・人物の牽制動作はSTRONG BOWL用の演出。ほかのゲームへ自動的に足さない。

## 録画で今回直した点

- F9に「MP4保存係を起動してください」と出る場合は、まず record-server.js の起動と8736番の接続を確認する。保存係は裏で起動し、余計な窓を出さない。
- 音の最終出口は、録画開始後の接続だけでなく、録画前に作られた接続も録音へ分ける。recorder-ui.js は出口の接続時に録音用の音声トラックを用意する。同じ出口を二重接続しない。
- 無音区間も録音の時計を動かし、映像と音声の相対時刻を維持する。録画開始前から鳴る音・途中で増えた効果音・2回目の録画を確認する。
- 再配布できない提供音源はゲームにもGitにも入れない。今回の効果音は合成音を使用した。

## 公開・検証時に忘れないこと

- 公開承認後に publish.js で下書きを移し、テストや道具の旧フォルダ参照も更新する。共有ページ・サムネ・一覧を確認し、関係ない変更を混ぜずpushする。
- GitHub Pagesの配信にはキャッシュがある。修正の到着を確認するときは公開ファイルの中身を調べ、手元だけで直ったことと公開反映を区別する。
- 3Dゲームは偽DOMだけでなく実ブラウザでも確認する。関節・姿勢の切り替え・カメラ・影の範囲・模型の底面などは画像と動作で確認する。
- 入力取消と通常の指離しを区別する。仕様を戻す依頼は、状態遷移や物理への切り替え時点まで差分を追って戻す。
